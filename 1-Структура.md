# Инструкция для ИИ-агента: Поиск дубликатов фото (SQLite)

## 1. Цель
Разработать приложение, которое сканирует папку с фотографиями, заполняет базу данных SQLite и находит дубликаты используя трехуровневый алгоритм:
1.  **Имя файла** (быстрый отсев).
2.  **EXIF данные** (сравнение метаданных).
3.  **SHA256** (сравнение бинарного содержимого).

## 2. Схема Базы Данных (SQLite)

Создай следующую структуру таблиц. Используй **транзакции** для пакетной вставки данных.

### Таблица `files`
| Колонка | Тип | Описание | Индекс |
| :--- | :--- | :--- | :--- |
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | PK |
| `file_path` | TEXT | Полный путь к файлу | UNIQUE |
| `file_name` | TEXT | Имя файла (basename) | INDEX |
| `file_size` | INTEGER | Размер в байтах | INDEX |
| `mime_type` | TEXT | MIME-тип (image/jpeg и т.д.) | INDEX |
| `sha256` | TEXT | Хеш содержимого (NULL если не вычислен) | INDEX |
| `exif_signature` | TEXT | Строка-сигнатура EXIF (NULL если не вычислен) | INDEX |
| `exif_dt_original` | TEXT | Дата съемки (YYYY-MM-DD HH:MM:SS) | INDEX |
| `exif_make` | TEXT | Производитель камеры | INDEX |
| `exif_model` | TEXT | Модель камеры | INDEX |
| `status` | TEXT | Статус: `new`, `exif_checked`, `hash_checked`, `duplicate` | INDEX |

### Таблица `duplicate_groups`
| Колонка | Тип | Описание |
| :--- | :--- | :--- |
| `group_id` | INTEGER | PRIMARY KEY AUTOINCREMENT |
| `match_type` | TEXT | Тип совпадения: `sha256` (основной), `exif`, `name` |
| `signature` | TEXT | Ключевая строка (SHA256 или EXIF-сигнатура) |
| `created_at` | DATETIME | Время создания записи |

### Таблица `group_files`
| Колонка | Тип | Описание |
| :--- | :--- | :--- |
| `group_id` | INTEGER | FK -> duplicate_groups.group_id |
| `file_id` | INTEGER | FK -> files.id |

## 3. Алгоритм Работы

### Этап 1: Сканирование и Инициализация
1.  Обойти целевую папку рекурсивно.
2.  Для каждого файла проверить наличие в БД по `file_path`.
3.  **Если файл новый:**
    *   Извлечь метаданные ФС: `file_name`, `file_size`, `mime_type`.
    *   Установить `status = 'new'`.
    *   Установить `sha256 = NULL`, `exif_signature = NULL`.
    *   Добавить в БД внутри транзакции.
4.  **Если файл существует:**
    *   Сравнить `file_size` и время изменения (`mtime`).
    *   Если файлы изменились: сбросить `sha256` и `exif_signature` в `NULL`, обновить `status = 'new'`.

### Этап 2: Поиск кандидатов по Имени Файла
1.  Выбрать файлы со статусом `new`.
2.  Найти группы файлов с одинаковым `file_name`, но разными `file_path`.
    ```sql
    SELECT file_name, GROUP_CONCAT(id) as ids
    FROM files
    WHERE status = 'new'
    GROUP BY file_name
    HAVING COUNT(*) > 1;
    ```
3.  Если группа найдена -> перейти к Этапу 3.
4.  Если группы с одинаковым именем нет, но есть файлы со статусом `new`, которые не участвовали в совпадениях по имени:
    *   *Опционально:* Можно сразу считать SHA256 для уникальных имен (оптимизация), но по ТЗ мы идем по цепочке. Если по ТЗ строго только для совпадающих имен — пропускаем. **Рекомендация:** Если файл уникален по имени, его SHA256 все равно нужно вычислить, чтобы исключить его из будущих дублей. Но для чистоты алгоритма "имя -> exif -> hash", фокусируемся на группах.

### Этап 3: Обработка EXIF для кандидатов
1.  Для каждого файла из найденных групп (Этап 2):
    *   Прочитать EXIF данные (используй библиотеку `Pillow` или `exifread`).
    *   Извлечь ключевые поля: `DateTimeOriginal`, `Make`, `Model`, `GPSLatitude`, `GPSLongitude`, `ImageWidth`, `ImageHeight`.
    *   Сформировать `exif_signature`:
        ```python
        # Пример логики
        sig_parts = []
        for key in ['DateTimeOriginal', 'Make', 'Model', 'GPSLatitude', 'GPSLongitude', 'ImageWidth', 'ImageHeight']:
            val = exif_data.get(key)
            if val is not None:
                if isinstance(val, tuple):
                    val = str(val) # Для GPS
                sig_parts.append(f"{key}={val}")
        exif_signature = "|".join(sorted(sig_parts))
        ```
    *   Обновить в БД:
        *   `exif_signature`
        *   `exif_dt_original` (отдельно для быстрого доступа)
        *   `exif_make`
        *   `exif_model`
        *   `status = 'exif_checked'`

### Этап 4: Поиск совпадений по EXIF
1.  Найти группы файлов со статусом `exif_checked` и одинаковой `exif_signature`.
    ```sql
    SELECT exif_signature, GROUP_CONCAT(id) as ids
    FROM files
    WHERE status = 'exif_checked'
    GROUP BY exif_signature
    HAVING COUNT(*) > 1;
    ```
2.  Если группа найдена -> перейти к Этапу 5.
3.  Если групп нет, но остались файлы со статусом `exif_checked` (уникальные по EXIF):
    *   Вычислить для них SHA256 (см. Этап 5 для всех остальных).

### Этап 5: Вычисление SHA256 и Финальное Сравнение
1.  Собрать список всех файлов, у которых `sha256 IS NULL`. Это включает:
    *   Файлы из групп EXIF-дубликатов.
    *   Файлы, которые не попали в группы по имени или EXIF (для полной очистки от дублей).
2.  Для каждого файла вычислить SHA256.
    ```python
    import hashlib
    def get_sha256(path):
        with open(path, 'rb') as f:
            return hashlib.sha256(f.read()).hexdigest()
    ```
3.  Обновить поле `sha256` в БД.
4.  Найти точные дубликаты:
    ```sql
    SELECT sha256, GROUP_CONCAT(file_path) as paths
    FROM files
    WHERE sha256 IS NOT NULL
    GROUP BY sha256
    HAVING COUNT(*) > 1;
    ```
5.  Соз записи в `duplicate_groups` (match_type='sha256') и `group_files`.
6.  Обновить статус всех обработанных файлов на `checked` или `duplicate` (если они вошли в группу).

## 4. Технические требования и Оптимизация

1.  **Производительность:**
    *   Всегда используй `BEGIN TRANSACTION` перед пакетной вставкой (например, 500-1000 записей).
    *   Включи `PRAGMA journal_mode = WAL;` для SQLite.
    *   Избегай чтения EXIF для файлов, которые уже имеют `sha256` (если они не новые). Но так как мы ищем дубликаты, лучше пересчитывать только если файл помечен как измененный.
2.  **Обработка ошибок:**
    *   Если файл удален во время работы, пропускай его.
    *   Если EXIF нечитаем, игнорируй поля EXIF, но продолжай вычисление SHA256.
3.  **Типы данных EXIF:**
    *   GPS координаты часто приходят как кортежи рациональных чисел. Приводи их к строке.
    *   `DateTimeOriginal` может быть в формате `YYYY:MM:DD HH:MM:SS`. Приводи к стандартному ISO формату для корректного сравнения.
4.  **Память:**
    *   Не загружай все пути в память сразу. Используй итераторы или пейджинг, если файлов > 100k.

## 5. Выходные данные
Программа должна выводить список групп дубликатов:
*   Группа ID
*   Тип совпадения (`sha256`)
*   Список путей к файлам
*   (Опционально) Показать, что они прошли фильтрацию по имени и EXIF.

---
**Важно:** ИИ-агент должен реализовать именно эту цепочку. Не вычисляй SHA256 для всех файлов сразу — это слишком медленно. Используй имя и EXIF как фильтры-воронки.
