Вот инструкция для ИИ-агента по проектированию и реализации графического интерфейса (GUI) для приложения поиска дубликатов фото.

# Инструкция для ИИ-агента: Проектирование GUI (Интерфейс Пользователя)

## 1. Цель и Технологический Стек
*   **Цель:** Предоставить пользователю интуитивно понятный интерфейс для управления процессом сканирования, визуального анализа дубликатов и контроля состояния базы данных.
*   **Рекомендуемый стек:**
    *   **Фреймворк:** `PyQt6` / `PySide6` (для высокой производительности и нативного вида) или `Tkinter` + `ttkbootstrap` (для простоты и легковесности).
    *   **Визуализация изображений:** `QImage`/`QPixmap` (Qt) или `Pillow` + `Tcl/Tk` (Tkinter).
    *   **Стилизация:** Темная тема (Dark Mode) по умолчанию, так как работа с медиа-контентом требует контраста.

## 2. Архитектура Интерфейса (Layout)

Интерфейс должен быть разделен на 4 основные зоны:

### Зона А: Верхняя панель управления (Toolbar)
*   **Выбор папки:** Кнопка "Выбрать папку для сканирования" (диалоговое окно `QFileDialog`).
*   **Статус-бар:** Отображение текущего статуса:
    *   `Готово к сканированию`
    *   `Сканирование... (X% выполнено)`
    *   `Обработка EXIF...`
    *   `Вычисление хешей...`
    *   `Найдено дубликатов: N групп`
*   **Кнопки действий:**
    *   `▶ Старт` (начать сканирование)
    *   `⏸ Пауза` / `⏹ Стоп` (управление процессом)
    *   `🗑 Очистить БД` (полное удаление записей, с подтверждением)
    *   `⚙ Настройки` (вызов модального окна настроек)

### Зона Б: Левая панель навигации (Sidebar)
*   **Дерево папок:** Отображает структуру отсканированных папок.
    *   Позволяет выбрать конкретную папку для детального просмотра.
    *   Фильтр: "Все файлы", "Только дубликаты".
*   **Фильтры:**
    *   По дате (диапазон дат).
    *   По производителю камеры (`exif_make`).
    *   По размеру файла.

### Зона В: Центральная область просмотра (Main View) — *Ключевой элемент*
Должна поддерживать два режима переключения:

#### Режим 1: Список (Table View)
*   Таблица с колонками: `Превью`, `Имя файла`, `Путь`, `Размер`, `Дата съемки`, `Статус`.
*   **Превью:** Миниатюра изображения (загружается лениво/асинхронно, чтобы не тормозить интерфейс).
*   **Интерактивность:**
    *   Клик по строке выделяет файл.
    *   Выделение нескольких файлов (Ctrl+Click) для групповых действий (удалить, переместить, сравнить).

#### Режим 2: Сравнение (Comparison View)
*   Появляется, когда пользователь выбирает группу дубликатов.
*   **Макет:** Сетка изображений (2x2, 3x3 и т.д.) внутри группы.
*   **Функции:**
    *   **Зум:** Возможность увеличить конкретное фото.
    *   **Навигация:** Стрелки влево/вправо для перехода между группами дубликатов.
    *   **Маркеры:** Визуальное выделение "оригинала" (например, зеленой рамкой) и "дубликатов" (красной).
    *   **Информация:** Под каждым фото отображается:
        *   Полный путь.
        *   SHA256 хеш (сокращенный, например, первые 8 символов).
        *   Размер файла.
        *   Причина совпадения (например, "SHA256 Match").

### Зона Г: Нижняя панель информации (Properties/Logs)
*   **Вкладки:**
    1.  **EXIF Данные:** Таблица с ключевыми полями выбранного файла (`DateTimeOriginal`, `GPS`, `Model`, `Lens` и т.д.).
    2.  **Лог операций:** Текстовое поле с логами работы программы (время, действие, статус). Должен поддерживать автопрокрутку.
    3.  **Инфо о БД:** Статистика: всего файлов, размер БД, количество групп дубликатов.

## 3. Логика взаимодействия с бэкендом (Backend Integration)

### 1. Управление сканированием
*   **Событие `on_scan_started`:**
    *   Блокировать кнопку "Старт".
    *   Запустить прогресс-бар.
    *   Подписаться на сигналы от воркеров (ProgressSignal).
*   **Событие `on_scan_progress(total, current)`:**
    *   Обновлять прогресс-бар.
    *   Обновлять статус-бар.
    *   *Важно:* Не обновлять UI чаще, чем 10 раз в секунду, чтобы избежать "дерганий".
*   **Событие `on_scan_finished(result_groups)`:**
    *   Разблокировать кнопку "Старт".
    *   Загрузить результаты в `Central View` (Режим сравнения).
    *   Показать уведомление "Сканирование завершено".

### 2. Визуализация дубликатов
*   **Ленивая загрузка (Lazy Loading):**
    *   Не загружать все превью сразу.
    *   Загружать превью только для видимых элементов в таблице или для выбранной группы.
    *   Использовать асинхронные задачи для ресайза изображений (чтобы не блокировать GUI поток).
*   **Кэширование превью:**
    *   Сохранить сгенерированные миниатюры в оперативной памяти или на диске (temp-folder), чтобы не пересчитывать их при повторном открытии.

### 3. Управление базой данных
*   **Очистка:**
    *   При нажатии "Очистить БД":
        1.  Показать модальное окно подтверждения: "Вы уверены? Все данные будут удалены."
        2.  Если подтверждено: Выполнить `DELETE FROM files`, `DELETE FROM duplicate_groups`.
        3.  Обновить UI: очистить таблицы, сбросить фильтры.
*   **Экспорт:**
    *   Кнопка "Экспорт отчета" (CSV/JSON) для сохранения списка дубликатов.

## 4. Критические требования к UX (User Experience)

1.  **Отзывчивость (Responsiveness):**
    *   Интерфейс **не должен зависать** во время вычисления хешей или чтения EXIF.
    *   Все тяжелые операции (хеширование, чтение EXIF, запросы к БД) должны выполняться в отдельных потоках/воркерах.
    *   Использовать `QThread` (Qt) или `asyncio` (Tkinter с `after`) для переноса обновлений UI в главный поток.

2.  **Обратная связь:**
    *   Если файл не читается (нет прав), показывать иконку ошибки и всплывающую подсказку: "Ошибка чтения: Permission denied".
    *   Если группа дубликатов большая (>10 фото), показать кнопку "Показать все" или пагинацию, чтобы не перегружать экран.

3.  **Управление памятью:**
    *   При переключении между большими группами дубликатов освобождать память от старых изображений (GC.collect или удаление ссылок на QPixmap).
    *   Не держать открытыми все файлы одновременно. Закрывать файловые дескрипторы после чтения EXIF/Хеша.

4.  **Обработка ошибок GUI:**
    *   Если БД повреждена или недоступна, показать диалог ошибки и предложить восстановить/очистить.
    *   Если пользователь закрывает приложение во время сканирования, спросить: "Продолжить при следующем запуске?" или "Прервать?".

## 6. Инструкция для ИИ-агента по реализации

1.  **Создать класс `MainWindow`:** Основной контейнер с сеткой (Grid Layout).
2.  **Реализовать `WorkerThread`:** Класс, который выполняет сканирование и хеширование в фоне. Он должен отправлять сигналы (`signal_progress`, `signal_result`) в основной поток.
3.  **Реализовать `ImageLoader`:** Отдельный модуль для асинхронной загрузки и ресайза изображений.
4.  **Связать события:**
    *   Клик по `Start` -> Запуск `WorkerThread`.
    *   Сигнал `progress` от `WorkerThread` -> Обновление `QProgressBar`.
    *   Сигнал `result` от `WorkerThread` -> Добавление записей в `QTableWidget` или обновление модели данных.
5.  **Добавить контекстное меню:**
    *   Правый клик по файлу в таблице: "Показать в проводнике", "Удалить из БД", "Сравнить с другими".
6.  **Тестирование:** Убедиться, что интерфейс не "зависает" при выборе группы из 50+ фотографий.

Эта структура обеспечит профессиональный, быстрый и удобный инструмент для пользователя.
